# 自我进化调度平台复用策略报告

版本：v1.0  
日期：2026-05-20  
目标：在“复用 LiteLLM 能力”的前提下，最小自建控制面，实现稳定、可维护、可迭代。

---

## 1. 战略判断

平台的长期竞争力不在“再造模型网关”，而在“控制面智能化”：
- 把 Skill / RAG / Agent / MCP 组装成可运营系统
- 让策略可学习、可发布、可回滚
- 让团队协作与治理流程产品化

因此，建议采用：
- 重复能力下沉到 LiteLLM
- 差异化能力沉淀在 Control Plane

---

## 2. 复用-自建决策矩阵

## 2.1 必须复用（LiteLLM）

- 多模型统一接入
- 路由、fallback、retry、cooldown
- virtual key/team/user 与预算
- spend/logging/call_id
- MCP gateway、A2A gateway
- 基础 guardrails

原因：成熟、通用、替换成本高、重复实现价值低。

## 2.2 必须自建（Control Plane）

- 工作流编排（业务节点+状态机）
- 知识治理（上传、切分、索引、版本）
- 策略进化（评估、学习、发布、回滚）
- 发布治理（审批、灰度、变更审计）
- 面向角色的产品工作台

原因：业务语义强、组织流程强、与平台价值直接相关。

## 2.3 可插拔（按阶段）

- 高级 guardrail 策略
- 成本优化策略引擎
- 自动 A/B 与流量分配

原因：先做最小闭环，避免一次性过度设计。

---

## 3. 目标架构（控制面中心）

## 3.1 分层

1. Gateway Layer（LiteLLM）  
- 负责模型调用、统一鉴权、路由、观测底座

2. Orchestration Layer（自建）  
- Workflow Engine：流程定义/执行/重试
- Policy Engine：规则计算/策略下发
- Registry：Skill/Agent/MCP 目录与版本

3. Product Layer（自建）  
- 用户工作台（项目、知识、流程、治理）
- 运营看板（质量、成本、稳定性）

4. Data Layer  
- 结构化元数据（Postgres）
- 向量索引（Qdrant）
- 事件与日志（OTEL + 日志存储）

---

## 4. 核心闭环设计

## 4.1 运行闭环

输入 -> 策略选择 -> 模型/工具执行 -> 结果评估 -> 观测沉淀

## 4.2 进化闭环

事件采集 -> 指标分析 -> 规则候选生成 -> 沙箱验证 -> 灰度发布 -> 全量生效/回滚

## 4.3 治理闭环

变更申请 -> 审批 -> 发布 -> 监控 -> 复盘

---

## 5. Skill/RAG/Agent/MCP 统一抽象

统一对象模型建议：
- Capability（能力定义）
- Version（版本）
- Binding（与 team/project/agent 绑定关系）
- Policy（启用条件、预算、权限、guardrail）
- Runtime Contract（输入输出契约）

这样做的收益：
- 可以统一发布和回滚
- 可以统一审计和追责
- 可以统一跨能力编排

---

## 6. 稳定性设计要点

- 全链路 request_id + trace_id
- 幂等执行键（避免重复执行）
- 任务级超时与补偿
- 按能力的降级策略（比如禁用高风险工具）
- 配置发布灰度与快速回滚

---

## 7. 可维护性设计要点

- 控制面 API 契约化（OpenAPI + 合约测试）
- 配置与代码分离（策略外置）
- 统一错误码与用户可操作提示
- 统一插件协议（Skill/Agent/MCP 适配层）
- 文档与测试同版本发布

---

## 8. 实施路线（建议）

## Phase A：最小可用闭环（2-4周）
- 打通上传 -> 检索 -> 调用 -> 观测
- 接入 LiteLLM key/team/spend/call_id
- 建立统一事件模型

## Phase B：控制面成型（4-8周）
- 工作流编排 V1
- 策略发布/回滚 V1
- 能力注册中心 V1

## Phase C：自我进化（8-12周）
- 质量评估器 + 策略候选生成
- 灰度策略自动化
- 成本与质量联合优化

---

## 9. 成功判据

- 新增能力接入周期下降 >= 50%
- 发布变更可回滚率达到 100%
- 故障定位时间下降 >= 60%
- 成本与质量指标均可按 team/project 追踪

---

## 10. 一句话总结

“网关复用，控制面自建，产品层做强。”  
这是把平台做成长期可演进产品的最优路径。
