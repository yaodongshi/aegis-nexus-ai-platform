# Team AI Platform 产品化整改方案（针对7个问题）

版本：v1.0  
日期：2026-05-20  
目标：把“可演示系统”升级为“可交付产品”，并给出验收标准。

---

## 1. 范围与原则

本方案覆盖你提出的7个问题：
1. 权限限制导致可用性差
2. 知识库上传入口缺失
3. 缺少流程化编排界面
4. 治理能力半成品
5. LiteLLM 能力边界不清
6. 观测能力偏占位
7. 用户管理入口重复

执行原则：
- 以“用户可达路径”优先，不做仅技术视角优化
- 先打通闭环，再做高级能力
- 所有描述以当前代码可验证事实为基线

---

## 2. 问题到改造项映射

## 问题1：权限链路正确但上手阻力大

现状：Team -> Project -> Agent/Knowledge 是强校验；新用户容易在创建阶段失败。  
根因：权限模型正确，但缺少引导与默认可用路径。

产品化改造：
- 新建 Team 后自动引导创建首个 Project（向导）
- 增加“快速开始项目”模板（预置 Agent、知识空间）
- 权限报错改成可操作文案（告诉用户下一步）

验收标准：
- 新用户 5 分钟内完成首个 Agent 创建
- 相关 403/422 错误中，80% 带明确下一步动作建议

---

## 问题2：知识库无文件上传

现状：前端知识页只有文本创建/搜索/删除。  
根因：后端入库路径偏 API 化，前端未提供用户化入口。

产品化改造：
- 增加文件上传入口（PDF/MD/TXT/DOCX）
- 增加上传任务状态（待处理、处理中、成功、失败）
- 增加批量上传和失败重试

验收标准：
- 用户在知识页可直接上传文件
- 上传后可查询到分片和索引状态
- 失败任务可重试且有错误原因

---

## 问题3：缺少流程化编排器

现状：治理页是动作按钮，不是流程设计器。  
根因：能力存在，但未形成“流程产品形态”。

产品化改造：
- 增加可视化流程编排 V1（节点：数据接入、清洗、向量化、规则生成、发布）
- 提供流程模板（研发规范同步、客服知识刷新、周报摘要）
- 支持手动执行 + 定时执行

验收标准：
- 至少 3 个官方模板可一键运行
- 流程运行有状态和日志
- 支持暂停、重跑、失败节点重试

---

## 问题4：治理能力半成品

现状：skill-sync/evolution 存在接口，但MCP语义与产品语义不一致。  
根因：接口命名偏底层 CRUD，缺少“任务编排层”。

产品化改造：
- 新增“治理任务层”API：发布技能包、回滚技能包、规则生效、策略仿真
- 增加“发布审批流”（至少二段：草稿 -> 已发布）
- 增加版本化与差异对比（配置 diff）

验收标准：
- 治理操作全部可回溯（谁、何时、改了什么）
- 任意发布动作可一键回滚
- 用户可在 UI 上看到版本差异

---

## 问题5：LiteLLM边界认知混乱

现状：LiteLLM 既被当网关，又被当“全栈智能平台”。  
根因：对外能力说明没有把“网关层”和“控制面层”拆开。

产品化改造：
- 发布统一能力边界文档（本次交付）
- 在系统中明确分层命名：Gateway / Control Plane / Runtime
- API 文档新增“能力归属标签”

验收标准：
- 关键能力均标注归属层
- 需求评审中不再出现“网关替代编排器”的误判

---

## 问题6：观测能力偏占位

现状：Git Hook 链路较完整，其它链路不完整。  
根因：缺少统一 Trace 与统一事件模型。

产品化改造：
- 统一 request_id/trace_id（贯穿前端 -> API -> LiteLLM -> 回调）
- 接入 LiteLLM call_id 映射到平台事件
- 增加三类看板：稳定性、成本、发布质量

验收标准：
- 90% 请求可在观测中心“一跳追踪”
- 成本、延迟、错误率可按 team/project/agent 维度查看
- 发布变更可关联故障时间线

---

## 问题7：用户管理入口重复

现状：/users 重定向 /settings，且 settings 里有 users tab。  
根因：导航设计未收敛。

产品化改造：
- 合并 IA：只保留一个“用户与权限”入口
- 提供“账号/团队成员/角色权限”三级结构
- 在导航层删除重复入口并做兼容跳转

验收标准：
- 导航不再出现重复入口
- 用户 2 次点击内到达任意用户管理功能

---

## 3. 分阶段里程碑

## P0（1-2周）可用性止血
- 上手向导（Team -> Project -> Agent）
- 知识库文件上传入口 V1
- 用户管理入口收敛
- 错误文案产品化

出口标准：新用户首日可跑通闭环。

## P1（3-5周）稳定化与流程化
- 流程编排 V1（模板+执行）
- 治理任务层 API + 版本/回滚
- 观测统一 ID 链路

出口标准：核心能力可持续运行，问题可定位。

## P2（6-10周）规模化运营
- 预算、配额、策略治理与看板
- 多团队策略隔离与审计
- 自动化回归与灰度发布体系

出口标准：可支撑多团队长期运行。

---

## 4. 风险与回滚

主要风险：
- 前后端契约不一致导致发布后故障
- 治理能力改造涉及历史接口兼容
- 观测接入后日志量暴增

应对策略：
- 建立 API 合约测试（CI 强制）
- 新旧接口双轨期 2 个迭代
- 日志采样和分级存储

回滚策略：
- UI Feature Flag 按模块关闭
- 治理发布支持配置回滚
- 数据迁移脚本提供反向回退脚本

---

## 5. 成功指标（业务视角）

- 新用户首日闭环完成率 >= 80%
- 知识上传成功率 >= 95%
- 治理任务失败可恢复率 >= 90%
- 可观测请求覆盖率 >= 90%
- 用户关于“入口混乱”反馈下降 >= 80%

---

- 文档：能力边界、操作手册、上线回滚手册
- 验收：测试报告、监控基线、灰度复盘
